# Card seeds: Idea-to-Live Factory

Generated by `pack/build_pack.py` from `pack/src/cards.json` (pack 1.0). Do not edit by hand.

Each seed is a unit of intent with an acceptance contract. The Director splits seeds into Factory cards after the Fit Report (C0.00); seeds are never merged, dropped or widened without an approved delta in AR-13.

## Phase 0: Protect, measure and operate

Protect governance, add trustworthy memory, measure the Factory live from day one, and give live operation an owner inside the Factory. Measurement is built in, not a study period.

**Entry:** AR-13 ratified; AR-14 admits Phase 0.

**Exit:** Every Phase 0 card accepted; Isa approves the phase exit through the interim gate (C0.02).

### C0.00 Fit Report: map the pack onto the existing Factory

The pack was written without access to the Factory's code. Before any other card is created, the Director reads the codebase and reports, card by card, what exists, what must change and what conflicts.

- **Owner after migration:** Planning. **Executed by:** Director.
- **Depends on:** none. **Approvals first:** AR-07. **Ratified by:** Isa (in AR-13).
- **Traces:** DQ2, R11, H3. **Open items:** OI-01, OI-04, OI-13.

Scope:
- For each card seed: the components it touches, classified KEEP / UPLIFT / REPLACE / NEW (the parked design's classification in docs/design-parked/constitutional-factory-design-notes.md §18 is the starting hypothesis, not a finding)
- Answer the parked coupling questions: how many call sites choose a model; does any code rewrite history rows; where workflow state lives; can adapters report usage and throttling; are tests separable from implementation paths; how the Factory changes its own governance code today
- Today's roster of models, their access routes and today's predetermined mapping (R11 start state)
- Where the Owner's hashed keys live and how adapters obtain usable credentials (OI-04)
- Proposed deltas: seeds to split, and any seed whose premise does not hold, with evidence

Acceptance:
- [ ] Every card seed in the pack appears in the report with a classification and the files or modules it touches
- [ ] Every open item marked 'Fit Report' in open_items has an answer or an explicit 'not determinable from code' with the reason
- [ ] No seed is dropped, merged or widened in the report; changes appear only as proposed deltas for AR-13
- [ ] The report cites file paths and commit for every claim about the codebase

Evidence: Fit Report document stored with the pack's manifest hash.
